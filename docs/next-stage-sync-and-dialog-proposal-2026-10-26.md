## 项目详情居中弹窗＋编辑保护

进度更新：总规划已单独授权实施“本机项目详情弹窗＋项目字段保护”，实现与分层验证记录见 `project-dialog-2026-10-26.md`。下面普通事项、新增表单及完整同步依然只是待实施提案，不因项目批次完成而视为已实现。完成/恢复的浏览器闭环及手机实测仍待人工验收。

先做局部 UI 批次，不改变事项存储格式、不顺带实现同步。

1. `App.vue` 保留 selectedProjectId，但从两处列表内挂载改成列表外唯一详情外壳，原列表不再被详情撑开。优先原生 dialog.showModal（目标手机先验支持），复用 `ProjectDetail.vue` 的字段/历史/保存/删除逻辑。必要时使用 Vue Teleport 避开父层裁剪，不新增大型组件库。
2. 外壳居中，背景遮罩；宽度 min(视口减边距, 既有卡片宽度)，max-height 使用动态视口和安全区，卡片内 overflow:auto。打开移焦、限制背景操作、关闭还原焦点；手机软键盘、横屏与长历史单独实测。
3. 先补 ProjectDetail 草稿边界：同字段再点只聚焦；切字段、切项目、×、遮罩、Esc、折叠、完成、删除均走同一 requestLeave。**已确认规则：有修改先自动保存，成功才关闭或切换；失败保留输入并阻止离开。主动取消才放弃未提交修改。** 不改成每次弹出多选确认。Esc 的原生 cancel 事件须 preventDefault 后走相同检查。
4. 项目草稿在当前页面内按项目 ID/字段持有，离开时按第 3 条处理；**刷新后恢复未保存草稿继续暂缓，不纳入下一批验收**。不要单纯监听收起就清空。历史追加仍只在实际 currentSituation 变化时发生。
5. **普通事项单列**：修复 editing 与 expanded 不一致的锁定，跨事项切换遵循“有修改先自动保存，失败阻止离开”；不允许隐藏编辑后永久禁用名称/完成；保留共用五类及已完成列表行为。
6. **新增表单单列**：ProjectCreate、日常提醒、重要日新增、分类新增及快速记录的关闭/切换/折叠/切来源适用同一自动保存规则，主动取消才放弃；分别保留现有成功后清空与失败留输入。刷新后的草稿恢复暂缓，不能借此扩大范围。

验收按操作而非测试数量：长卡片水平垂直居中、原列表高度不变、卡内滚动；离开有修改时先自动保存，成功离开，失败保留并阻止离开，主动取消才放弃；普通 A→B→A 不锁定；新增表单切换遵循同一规则；桌面键盘、手机 Edge 和桌面入口软键盘均实测。旧数据、备份往返、完成恢复及学习注释回归。刷新后的草稿恢复不在本批验收。

## 最终离线同步方案（另批确认）

最终日常流程：本机编辑 → 本机事务保存 → 联网自动同步 → ChatGPT 读取服务端已确认内容。首次连接/增加权限授权后按已获权限自动续期，30 天或被撤销后再显式授权；不引入固定前端密钥。PWA 关闭后不保证后台运行，至少打开/回前台/联网时自动补传。

| 实际缺口 | 建议最小接口/协议 | 验收 |
| --- | --- | --- |
| 普通事项改名、标签、优先/紧急及类型字段修改 | 带 requestId、expectedVersion 的白名单 PATCH /api/items/:id，按类型复用现有业务规则 | 五类/日期/日常支持矩阵与非法字段拒绝 |
| 普通完成/恢复；随笔转换关系 | 明确 set-completed(true/false)，不能用可重复翻转 toggle；转换需原文与新项原子事务 | 重试不会二次翻转或多生成目标 |
| 删除 | CAS 删除标记而非物理移除；关联解除仍原子执行 | 旧设备重连不复活已删项 |
| 增量获取与 GPT 改动下发 | 单调 change sequence/cursor，包含 tombstone；分页固定高水位，不能只按 updatedAt 时间戳或 offset | 并发写入不漏变更，游标恢复可重复 |
| 新建的稳定身份/首次迁移 | 显式客户端 UUID 或 import 映射协议，保留本机与服务 ID 映射；目前 create 是服务端生成 ID | 重装/重试不重复，转换关系保持 |
| 回执保留期 | 和客户端允许离线时长配套；过期请求禁止盲目再次执行，先核对操作身份 | 长期离线不会因回执清理变成重复创建 |

本机当前是 localStorage 单份 v2 JSON，不能把“业务保存”和另一数据库 outbox 分两步就宣称原子。建议建立独立 IndexedDB records/outbox/meta 的事务：同一事务保存本机修改与待同步操作，成功后更新 Vue；备份仍输出兼容 v2。此变更需明确本地读写入口迁移并解决多页旧快照覆盖，不能只为 App.saveTasks 加 fetch。

操作包含 owner 固定身份范围、deviceId、operationId/requestId、稳定 itemId、baseVersion、patch、schema、创建顺序、状态。首次发出后 payload 不再修改；结果不明重试同 ID 同内容。对同一事项串行发送，后续编辑成为依赖前操作的新操作；未发出的连续编辑才可安全合并。联网/前台自动处理，指数退避＋抖动，401 先续期一次、权限过期提示连接；退出停止同步并丢弃迟到响应，但保留未同步本机记录。

服务端先查回执再 CAS。冲突保留本机与云端两份及共同基准；不做默认最后写入者覆盖。可明确展示字段差异，人工选定再以新版本、新 requestId 提交；无交集字段的自动合并需要单独规则和测试，首批不默认开启。GPT 的修改通过相同 change feed 下发，更新未编辑记录；正在编辑的草稿不被后台覆盖。

删除采用 versioned tombstone 和变更日志，旧设备的旧版本更新必须被拒绝；“不存在就创建”不能绕过删除。墓碑保留/设备确认水位、最长离线期需先确定；暂不物理回收，或长期未联设备强制全量重建并保留未同步草稿。显式恢复应是新操作，不能通过旧快照隐式复活。

首次纳入：只读扫描本机与云端 → 展示计数/类型/重复 ID/关联映射预览 → 用户选择以哪台设备为首份、哪些记录纳入 → 明确确认 → 分批带固定映射与幂等 ID 上传 → 逐条服务端确认再标已同步。本机数据在确认前始终独立；不同设备的重复内容不靠标题自动合并。虚构测试库与正式工作集如何分隔需单独确认，不能直接把现有正式事项导入测试库。

建议后续批次：A 弹窗与草稿保护；B 服务 CRUD、删除标记/增量协议；C IndexedDB 本机事务与 outbox、隔离故障验证；D 首次纳入预览确认及多设备/GPT 真实同步。各批分别验收，不能将 1B 手动写入叫作完整同步。

参考：[Apache CouchDB 复制协议](https://github.com/apache/couchdb/blob/main/src/docs/src/replication/protocol.rst)、[Apache PouchDB 复制指南](https://github.com/apache/pouchdb/blob/master/docs/guides/replication.md)。借鉴版本、变更游标、断线重试和删除传播原则；不引入 CouchDB、不迁移 Cloudflare、不照搬示例中的 URL 密码。
