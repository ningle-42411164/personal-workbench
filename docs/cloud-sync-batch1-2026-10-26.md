## 当前调用链与代码学习索引

1. `App.vue` 的 `saveTasks`：原首页生成完整 v2 下一状态，等待本机提交成功才更新画面、清空输入；所有使用返回值的创建/编辑路径已改为等待 Promise。
2. `src/sync/useSyncWorkbench.js`：Vue 状态、连接变化、前台/联网事件及跨窗口通知。通知只传 `changed`，不广播事项或令牌。
3. `src/sync/syncStore.js`：`save` 同时持久化事项和 dirty 状态；`prepare` 固定一次请求；`acknowledge` 只确认匹配请求，发送中产生的新修改继续保留；`applyChanges` 在同一事务更新数据与游标。
4. `src/sync/syncEngine.js`：`run` 串行发送、核对回执，再固定高水位拉取；断网或结果不明自动重放原请求；`interrupt` 与事务内 allowed 检查阻止退出/暂停后的迟到响应落盘。
5. `src/sync/syncApi.js`：共享 OAuth 连接，仅内存访问 access token，401 最多续期一次。确认记录 ID、版本、删除状态和内容符合原请求后才清队列。
6. `services/workbench-api/src/http.js → service.js → domain.js → store.js`：HTTP 路由、所有者/scope 上下文、严格输入和 v2 校验、D1 CAS+回执+变更日志原子提交。不存在匿名同步或前端固定私钥。
7. `SyncSettings.vue`：页尾默认收起的“云端连接”内部，提供一次开启、暂停、首次纳入预览和冲突核对。正常首页用于日常编辑，独立云端测试视图保留作诊断。
8. `OrdinaryItem.vue` / `ProjectCreate.vue`：等待本机事务返回成功；失败不把 Promise 当成 true 而清空输入。普通编辑中的记录固定留在原分组，外部完成/删除不卸载输入；保存时比较编辑基准。
9. `src/data/projectEditor.js`：保留同字段重入、自动保存后离开、主动取消等现有规则；同一字段在编辑期间被外部修改时阻止覆盖，输入仍在。没有改写历史追加机制。

原 `src/data/workbenchData.js` 与 `userTags.js` 的业务规则、学习注释保留。启动动画偏好继续原键；不是把启动偏好迁入同步队列。其他原有未提交学习改动不纳入本批提交。

## 存储、冲突与恢复约定

- IndexedDB `personal-workbench.local-sync.v1` 的单条状态包含 v2 data、绑定版本、dirty、不可变 outbox、冲突及游标。事务之外才等待网络；保存失败不返回成功。
- 迁移只在本设备复制原 v2，不发网络请求。原 LocalStorage 内容不覆盖；若检测旧缓存窗口又写了旧存储，暂停保存并提示核对备份，避免静默覆盖。更新时应关闭旧版工作台窗口。
- 多窗口保存比较本机 revision，旧快照被拒绝。多个发送窗口即使重放同一请求，也由服务端唯一回执去重；迟到旧回执不能回退已经确认的新版本。
- 冲突期间拉取不能覆盖本机待同步内容。人工“保留本机副本并采用云端”保留基准/双方归档，另生成本机副本；副本不会自动上传，需再次预览确认。
- 删除在服务端保留版本墓碑，旧 ID 的创建/更新不会复活；删除转换目标时沿用原规则解除关联，随笔保留。
- 已有同步绑定时阻止整份备份覆盖，防止将本机导入意外变成云端批量删除；纯本机尚无绑定时仍可正常导入。v2 导出不包含凭证或同步内部元数据。
- 首批增量拉取只合并待办与项目；后续增加其他类型时须升级同步协议并重新扫描对应快照，不能沿用已经跳过那些分类的旧游标假装完整。
- 单次请求上限仍为 64 KiB；超限事项保留本机并单独阻塞，其他事项继续。长历史分片/正式数据兼容需下一批处理，不能为了通过而删历史。

- workerd + OAuth + D1 验证新增 PUT、读取墓碑、完成与 DELETE 路由及增量日志；外连禁止，身份与数据均虚构。CORS 仅原有允许来源，新增 PUT 预检，权限校验未放宽。
- 原生 Edge 隔离页：从原首页新建虚构待办；更新应用和整页刷新后记录/队列保留；未登录明确提示等待登录；首次纳入预览默认不勾选；项目修改后关闭保存成功、仅增加一次原规则历史；普通待办完成/恢复通过。
- 两个原生 Edge 隔离窗口：A 留着未提交名称，B 完成同一事项；A 输入仍在，旧编辑保存被拒，未覆盖 B 状态。测试页仅含虚构数据、没有真实凭证，检查后已自行关闭，预览服务器停止。没有要求用户操作未知隔离页。

## ChatGPT 回复加载故障单列

- 最小只读请求为 `list_items(includeCompleted=true, limit=1, offset=0)`，没有再次写入事项。实际页面仍显示“无法加载此回复”。
- 依据官方 MCP 工具输出约定，为返回 structuredContent 的工具声明 outputSchema，保留兼容 JSON text；本地真实 SDK 确认二者一致、没有 UI 模板依赖。测试夹具的记录/分页结果约 333–501 字节；这不是实际手机会话响应的测量。
- 临时 Worker 诊断仅工具名、success、结果类型、UTF-8 字节数和随机关联号。原始 tail 事件在内存中白名单过滤，未输出/落盘授权 URL、请求头、令牌或事项正文，检查后停止。
- 最近一次最小请求未取得新的安全完成事件，因此尚不能证明故障在工具调用、返回解析还是回复展示阶段；不能据此无证据归因平台，也不能说 outputSchema 已修复问题。
- 既有真实 MCP 成功读取与唯一 v4 写入证据见 `mobile-cloud-1b-2026-10-26.md`。当前只承认数据闭环，完整回复体验未通过。
