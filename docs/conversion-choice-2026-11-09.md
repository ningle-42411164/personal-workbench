# 2026-11-09 分类拒绝的版本选择

版本 2026.11.09.2，范围仅为分类转换拒绝的处理。正式事项未在开发验收中写入。

## 调用链与规则
- syncEngine.run：已保存 IMMUTABLE_FIELD 且无 remote 时，仅 GET 获取双方对照，不重发拒绝请求。读取失败保留状态。
- SyncSettings：复用采用本机/采用云端与确认选择；展示真实双方内容、版本和拒绝代码。
- resolveConflict：沿用现有重新读取、revision/displayed 对照校验。云端再次变化只更新对照并要求重新选择。
- syncStore.resolveWithLocal → conversionStep：目标内容冻结进 resolutionTarget；未完成 todo 先通过原 returnTodo 退回 note，再通过原 initialMoveSnapshot 移动到合法目标，必要时提交同分类的内容修改。用户只确认一次。
- syncStore.acknowledge：每步回执在本机事务中推进绑定及下一请求，最后确认前保留 resolving；未知结果重用原 requestId/内容。服务端仍执行原 expectedVersion/CAS、认证和类型校验。
- 原拒绝请求在选择时完整归档；每个中间步骤和回执同样归档。原事项 ID 不变，不新建业务记录。
- resolveWithCopy：采用云端，按原规则保存本机冲突副本；额外保留被替换的原请求。
- 不支持的分类路径或关联组跨分类保留双方并报错，不将多条关联记录拆开部分转换。普通同分类关联组选择保持原规则。

中间合法状态可能暂时出现在云端。此流程是带版本校验的多步转换，不宣称跨请求原子性。若期间别端修改，停止并重新展示双方；不会自动替用户选择。
